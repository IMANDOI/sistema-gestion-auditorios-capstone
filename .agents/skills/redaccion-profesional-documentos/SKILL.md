# Skill: Redacción Profesional de Documentos Técnicos y Académicos

Esta habilidad se activa cada vez que se redacta, actualiza o revisa un documento técnico, informe de avance o memoria de título.

## 1. Tono y Estilo de Redacción
* **Voz y Persona:** Redactar en tercera persona impersonal ("se implementó", "se diseñó") o plural de autoría formal ("el equipo desarrolló"). Jamás usar tono conversacional informal ("arreglamos", "hicimos una pantallita").
* **Rigor Terminológico:** Utilizar vocabulario exacto de la disciplina:
  * ❌ *Evitar:* "la base de datos se conecta a la página".
  * ✔️ *Correcto:* "persistencia relacional gestionada mediante Prisma ORM bajo protocolo TLS/SSL hacia clúster serverless PostgreSQL".
  * ❌ *Evitar:* "se arregló la cámara".
  * ✔️ *Correcto:* "optimización del pipeline de captura en Canvas HTML5 con recorte nativo y tolerancia de contraste invertido".

## 2. Fórmula Obligatoria para Justificar Ajustes (Criterio 1 de Rúbricas)
Cada vez que se declare un cambio, mejora o ajuste respecto a la planificación original, es **mandatorio** desglosarlo en 4 secciones explícitas:
1. **Dificultad Encontrada:** Descripción concreta del problema técnico, operativo o limitación de infraestructura.
2. **Facilitador Aprovechado:** Herramienta, librería, estándar o recurso tecnológico que viabilizó la solución.
3. **Retroalimentación Docente / Usuario:** Observación académica o necesidad del usuario final que motivó el cambio.
4. **Justificación Técnica y Operacional:** Justificación de arquitectura, rendimiento, latencia o seguridad, indicando el impacto medible en métricas reales.

## 3. Estructura Visual de Documentos
* **Encabezados Jerárquicos:** H1 (Módulos/Secciones), H2 (Submódulos), H3 (Aspectos técnicos específicos).
* **Tablas Informativas:** Encabezados con fondo azul oscuro institucional, texto blanco y celdas alternadas en gris tenue.
* **Cajas de Alerta (Callouts):** Destacar conceptos críticos, decisiones arquitectónicas o preguntas clave para la comisión.
